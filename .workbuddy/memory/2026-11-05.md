## v1.8.0（G5.1）— 用户验收 v1.7.0 的四问，全部落地并出包

> 工作从 11-04 23:34 用户反馈开始，跨零点完成，记录归到本日。

- **用户四问与拍板**：① 默认仍磁盘缓存优先，新增设置项让用户自己切「本地文件优先」；② 设置页显示歌词磁盘缓存真实路径；③「只要查到歌词、本地目录没有就存一份」；④ 落盘名改「歌名 - 歌手」（带空格），英文保留原始大小写。
- **最关键的事实**：用户机器上 `本地歌词目录\Barline\` 一直是空的、`lyrics-cache` 有 93 个文件 —— **v1.7.0 不是没实现落盘，是只挂了一条路径**（内存/磁盘命中都 `return` 走了）。用户问「为什么要删 `lyrics-cache`」的根源就在这：只有删缓存才能让落盘生效。现在三条路径都落，且给了「本地优先」开关，**不再需要删缓存**。
- **用户二次裁决（推翻了 PRD 初稿与 PM 的两难申报）**：`local_first=true` 时顺序是 **本地 → 内存 → 磁盘**（不是「内存 → 本地」）。理由：内存 LRU 无 TTL，内存在前会让「正在播放那一首」手改后仍显示旧副本。本地命中后 `cache.put` 同时刷内存与磁盘。
- **实现**：`Step{Mem,Disk,Local}` 数组 + 单循环（两条顺序只写一份逻辑）；`maybe_write_back` 唯一收口（`source=="local"` 与 `!write_back` 各一份判定）；`Cache::get_mem/get_disk` 返回 `Hit{lyrics,source}`（磁盘回填必须带 source）；`display_stem` + `check_stem`（保留名 / ≤120 码元 / `n(stem) ∈ candidates`），`Unsearchable` 且 artist 非空 → **回退 title-only**；`locate.rs` 零 diff。
- **UI**：`lyrics.local_first` 开关（文案写明两种顺序的代价）+ 只读缓存卡片（路径 / 文件数 / 大小 / 「点击打开文件夹」，进分区读一次，零定时器）；新动作 `lyricsCacheStats` + 新消息 `cacheStats` + `SettingsService::post()`（**`push()` 会覆写 `last_state`**，重开窗口控件全空白）。
- **交付**：523 `#[test]` / 522 passed / 1 ignored（基线 494 → +29）；check/clippy/test/build 全绿、clippy 0；版本 5 处 + lock 1 行；包 `deliverables/曲栏_Barline_v1.8.0.exe` = 1,125,376 B / FileVersion 1.8.0；历史 35 包只增不删；提交 `890c07f`。
