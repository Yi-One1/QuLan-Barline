## 关键结论（必须记住）
- 曲栏**不是任务栏子窗口**（`host.rs` `parent=None` 的 top-level popup），`WS_EX_TOPMOST` + 每秒 `ensure_on_top()` 是全屏盖不住的根因。FluentFlyout 用 `SetParent(Shell_TrayWnd)` 变子窗口天然跟随；本轮按用户拍板**不改 SetParent**。
- **`HWND_NOTOPMOST` 是陷阱**：它只是「放到所有非 topmost 窗口之上」，对 F11 / 无边框全屏游戏仍会盖上去。必须用 **`HWND_BOTTOM`**（一次调用同时清 topmost + 落到底），恢复用 `HWND_TOPMOST`。「插到任务栏窗口之后」也被否决（顶层窗口之间无 Z 序跟随；曲栏窗口矩形完全落在任务栏矩形内，低于任务栏常态不可见）。
- appbar 注册在 **widget 主窗口**（`TaskbarCreated` 是广播，`HWND_MESSAGE` 收不到）；纯通知型，只 `ABM_NEW/ABM_REMOVE`，**故意不发 `ABM_QUERYPOS/SETPOS`、不占工作区**；`ABM_REMOVE` 必须在 `host.destroy()` 之前。
- `frozen` 重定义为「全屏遮挡态：窗口**仍 visible**，只降 Z 序 + 静止降载」；`compute_visible()` 删 frozen 分支；新增 `z_demoted`（`AppState` 期望态 + `TaskbarHost` 已应用态，幂等、只在 `SetWindowPos` 成功后翻转）；整套 resume 机制删除。退出顺序「**先清 `frozen/z_demoted` 逻辑门控，再恢复 `HWND_TOPMOST`**」，否则 `ensure_on_top` 双保险会把恢复动作自己挡掉。
- **R1 竞态（QA 发现、出包前修）**：`AppbarOpen` 不能沿用 `frozen_decision`，否则「通知早于前台窗口切换」时 `fs=false` 会把刚降的 BOTTOM 在同一 WndProc 内还原、退回 1s。改为 `!(fs && !same_monitor(fg, wm))` —— 信任事件、仅「明确异屏」还原；`Timer`/`AppbarClose` 与三个纯函数逐字不动。

## QA 最终增量报告的精确口径修正（出包后到达，代码与包不动）
- 主理人此前说「副屏不变量保住」**不够准确**：`occlusion_want(AppbarOpen) = !fs || same_monitor(...)`，**`||` 短路使 `fs=false` 时 monitor 完全不参与判定** → 「monitor 全 0 不冻结」（v1.4.4 起钉死）在**事件路径被有意识放宽**；只有 `fs=true` 路径 100% 保住明确异屏 / 任一侧全 0 立即还原（`AppbarClose` 强制 false、`Timer` 严格 `frozen_decision` 亦未被污染）。
- 真实影响：`widget_monitor` 为 `RECT::default()`（启动早期 / `geometry::probe()` 失败 / `WM_DISPLAYCHANGE` 瞬间）时一条 TRUE 广播会**完整冻结含降载** ≤1s，由 1s 心跳按严格 `frozen_decision` 恢复；窗口始终 visible、永不 `SW_HIDE`、无残留状态。真值表把 `fs=false × 全 0 → true` 钉成契约（有注释与等强度反向替代断言），属**契约重定义**而非静默删。
- 另两个破口：① `fs=false` 是**完整进入遮挡/降载**，不只是「仅 Z 序预降」，误判时用户看到内容停更 1s；② 迟到/重复的 TRUE 广播（close/open 乱序、Explorer 重启后 `appbar_reregister()` 补发）在 `fs=false` 下可**立即**补冻、不再等心跳。
- **QA 仍判 `PASS-WITH-NOTES` / 可出包 / 路由 `NoOne`**：R1 已修复、工程判断成立、破口概率极低且 ≤1s 可自愈，**不阻塞出包**。v1.5.7 首选加固：`AppbarOpen` 分支先判 `fg == RECT::default() || wm == RECT::default()` 则回退 `frozen_decision(fs, fg, wm)`，恢复 monitor 全 0 安全方向；正常竞态下 monitor 已知，不牺牲 R1 修复效果，不引入新状态/定时器。
- 教训：**给工程师写「安全方向保持」spec 时必须逐路径核对短路求值**；`!fs || same_monitor(...)` 会让 monitor 在竞态分支完全失效。
