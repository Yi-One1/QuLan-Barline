### v1.14.3 真根因（两次假设都错了）

现场日志：Edge 与夸克都有 SMTC 会话、又都不在白名单里，Windows「当前会话」**每秒在两者间翻一次** → `enter_ignored()` 只按「忽略身份变了」判重 → **每秒发一条 `SessionCleared`** → UI 收到无条件 `interact.reset()`（`hover = Idle`、`hover_alpha = 0`）→ 底板亮一下就没；`WM_MOUSEMOVE` 只在鼠标真动时才来，所以再也不回来。

两处修：
1. media 层：`PollState` 新增 `cleared_sent` 闸 —— 忽略态内部身份翻转只更新托盘文案（`IgnoredSession`），不重发 `SessionCleared`；真发布 `NowPlaying` 后清回 `false` 重新武装。
2. ui 层：新增 `Interaction::reset_session()`，只清 pressed/down/pending/seeking/hud/hover_target，**保留 hover/hover_alpha**；`SessionCleared` 处理另加幂等短路（已 NoSession + 图标态直接返回），顺带消掉每秒一次的 `Effect::Relayout` 窗口重排（那才是「假 WM_MOUSELEAVE」的来源）。

### 排查教训（重要）

- **日志有两份**：活动的是 `<数据目录>\barline.log`（本机 `E:/APP/曲栏Barline/数据目录/barline.log`）；`%LOCALAPPDATA%\Barline\barline.log` 只有启动几行，是残留。**看错文件会得出完全相反的结论**（04:00 那次就误判成「悬停没被清掉」）。
- 诊断日志只在 `hover_alpha >= 0.9` 时打，`reset()` 路径把 alpha 归零 → **静默**。「没有日志」≠「没发生」。
- 排查顺序：先看时间相关性（1 秒 = 心跳/轮询周期）→ 再找同一时刻的状态变更点。
