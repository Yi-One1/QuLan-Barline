## 2. 产品定义

### 2.1 产品目标（3 个，正交）

1. **前景可读**：三类元素随壁纸亮度**统一**切黑 / 白二值，任一壁纸下主文字对比度 ≥ 4.5:1（WCAG AA）；任务栏透明背景与 TranslucentTB clear 效果**保持不变**，只改前景。
2. **零副作用、可完整回退**：仅用户态 hook / 子类化任务栏窗口树；其它应用 / 窗口的配色与主题**视觉上不变**；环境探测不匹配即 fail-safe 自动禁用（不 hook、只记日志）；退出 / 异常均完整恢复系统原状。
3. **可验证、可交付**：Go/No-Go 先行；以真值表、源码静态断言、测试替身、反向验证、结构化日志为**主证据**（截图为辅）；六组逐组提交，只在最后一组出一次包并一次性升 v1.11.0，全量回归通过。

### 2.2 非目标（明确不做，均来自 §3 拍板）

- 不改任务栏透明效果、不改背景 / 强调色 / 模糊。
- 不取壁纸主色、不做灰度中间色、不分级着色；托盘图标不反色、不描边、不保留各自彩色。
- 不用内核驱动、系统资源替换、强制重启 Explorer；不用全局注册表主题 / 强调色路线（已否决）。
- 不照抄 CTM 工具；自研。
- 首版不覆盖 Win10 / 更早 Win11 / 四方位 / 副任务栏 / 自动隐藏 / TranslucentTB 其它档位。
- 小组件本体不新增任何按钮、不改既有播控 / 歌词 / 悬停 / 双击交互。

### 2.3 用户故事（5 条）

1. **作为**用 TranslucentTB 做纯透明任务栏的壁纸美化党，**我想要**切换深浅壁纸时时间、托盘图标、运行指示条自动一起变黑或白，**以便**不用来回改系统主题、也不会出现「浅壁纸上白字看不见」。
2. **作为**怕改坏系统的稳妥用户，**我想要**环境不匹配时软件自动不动、只写一条日志，退出后系统恢复原状，**以便**随时可以放心卸载或关闭。
3. **作为**同时开很多窗口的办公用户，**我想要**只有任务栏前景变、其它窗口的配色与主题一点不变，**以便**全局观感不被破坏。
4. **作为**不想进设置页的用户，**我想要**托盘里有一键开关，**以便**随时启用 / 停用这套自适应。
5. **作为**验收者 / 后续维护者，**我想要**每次翻色都有可机读的结构化日志和能故意改坏就变红的测试，**以便**不靠肉眼盯截图就能判定三类元素确实随壁纸切换。

## 7. 验收标准（可观察可判定）

> **证据优先级（§3 第 7 项）**：结构化日志 > 真值表 / 纯函数单测 > 源码静态断言 > 测试替身端到端 > 反向验证 > 截图（辅助）。**不以「测试全绿」代替「行为正确」**；反向验证是「测试全绿但功能没做」的唯一防线。

### 7.1 决策事件的数据契约（结构化日志，P1-01）

每次亮度决策产出 1 条 `foreground.decision`，每次应用产出 1 条 `foreground.apply`：

| 字段 | 含义 |
| --- | --- |
| `seq` / `epoch` | 样本序号 / 几何代次（与 `LumaStabilizer` 同源） |
| `luma` | 背景相对亮度（0..=1） |
| `on_light` / `color` | 稳定结论 / 黑或白二值 |
| `reason` | `first_frame` / `dead_zone` / `confirm` / `fast` / `cooldown` / `epoch_reset` |
| `wallpaper_change` | 本次是否由壁纸切换触发 |
| `elapsed_ms` | 从壁纸切换事件到决策落定的耗时 |
| `target` / `monochrome` | 仅 `foreground.apply`：`clock` / `tray` / `indicator`；托盘是否单色化 |
| `env` / `disabled_reason` | 环境快照 / 自动禁用原因（仅禁用路径） |

### 7.2 「三类元素颜色随壁纸切换」怎么判定（核心判据）

| # | 判据 | 判定方式（可自动化） | FAIL 条件 |
| --- | --- | --- | --- |
| V1 | **同源同色** | 同一 `seq` 的三条 `foreground.apply`（clock / tray / indicator）的 `color` 必须**全部等于**该 `seq` 的 `foreground.decision.color` | 任一不等 = 三类策略不统一 |
| V2 | **随壁纸翻色** | 测试替身依次注入纯黑壁纸（luma≈0.02）→ 纯白（≈0.98）→ 纯黑；断言决策 `color` 序列 = `[白, 黑, 白]`，且每个 `seq` 三条 apply 同步 | 序列不符 / 某一类滞后或漏应用 |
| V3 | **约 1 秒生效** | `wallpaper_change=true` 的决策，从切换事件到该 `seq` 三条 apply **全部**落定的 `elapsed_ms` 满足约定窗口（数值见 §10 Q2） | 超窗 / 某一类未落定 |
| V4 | **阈值不翻色** | 死区（0.12..0.25）与确认区 / 死区来回抖动序列下，`color` 恒定不变，`reason` 落在 `dead_zone` / `confirm` 复位；复用 `LumaStabilizer` 既有 12 条测试全绿 | 出现任意一次 `color` 变化 |
| V5 | **对比度达标** | 每个决策 `color` 与该 `luma` 等效灰按 `theme.rs::contrast_ratio` 计算 ≥ 4.5:1；中灰（≈0.216）必须选深色字 | < 4.5 |
| V6 | **托盘统一单色化** | `target=tray` 的 apply 必须 `monochrome=true` 且 `color` ∈ {黑, 白} 二值集合；断言输出中无原彩色、无反色、无描边产物 | 出现彩色 / 反色 / 描边 |
| V7 | **只改前景** | 决策与应用的产物中**零**背景色 / alpha 写入、零全局注册表主题 / 强调色写入、零其它 HWND 前景写入 | 出现任一越界写入 |
| V8 | **其它窗口视觉不变** | 日志断言「零其它窗口写入」+ 用户抽样截图辅助比对（G9 前后同场景） | 出现配色 / 主题变化 |

## 9. 风险与红线

### 9.1 用户已拍板的红线（不可触碰，来自 §3）

1. 禁止内核驱动、系统资源替换、强制重启 Explorer；只用用户态 hook / 子类化任务栏窗口树。
2. 禁止全局注册表主题 / 强调色路线（已否决）；其它窗口配色 / 主题**视觉上不能变**。
3. 任务栏透明效果保持不变；只改前景三类元素。
4. 黑白二值择优、不取壁纸主色、三类统一策略；托盘图标统一单色化（不反色 / 不描边 / 不保留彩色）。
5. 组 ① No-Go 即停下重议，不得带疑点进入产品代码。
6. 环境不匹配一律 fail-safe 自动禁用；必须完整回滚、退出恢复系统原状。
7. 中间组只提交源码、不出包、不升版本；只在组 ⑥ 出一次包、升一次 v1.11.0；`deliverables/` 只增不删。
8. 构建只走 `scripts/build.ps1`，禁裸 cargo；每组提交后主理人汇报「任务清单 + 进度」。

### 9.2 待架构师评估的风险（PM 识别，不自行决定）
